## Code in this PR

1. **Migration:** remote_wipe_commands, globally unique target-device operation and operation UUID, immutable account/actor/target/revision plus signed command evidence. Successful insert requires target already revoked; this service does not revoke it.
2. **Domain:** App/RemoteWipe/SignedDeferredCommand with exact versioned device-local-only wire payload, account-root and active actor-device P-256 signatures, server-authenticated actor/account binding, account→actor→target transaction locks and strict revision validation.
3. **Idempotency:** exact signed retry preserves one operation; new operation for same target and altered original digest fail closed (409).
4. **Target receipt:** only the original target signing SPKI signs a separate domain-separated receipt tied to original SHA-256 and operation/account/target. A duplicate signed self-report is idempotent. **A signature does not independently prove physical local erasure.**
5. **Honest statuses:** wipe_pending vs target_reported_local_wipe, always localWipeProven=false, matrixRemoteRevoked=false, cloudDeleted=false, backupDeleted=false. No S3, Recovery Vault, Matrix or unrelated device mutations.

## NOT RELEASE-READY

- **No HTTP route** is mounted. A revoked target cannot yet receive/poll/acknowledge the command through a verified bounded delivery transport; browser/local executor is missing.
- Revocation (#80) and durable command insertion are **not yet atomic**. Once the signed #80 path has passed acceptance and integration is authorized, join revoke+persist in one transaction. A non-atomic gap must never count as completed Remote Wipe.
- The browser must require explicit target confirmation and trusted session, maintain an encrypted durable command/outbox, deny offline false success and report lost ACK honestly.
- Full remote Matrix token revoke requires separate homeserver authority. **Ordinary device revoke must preserve Recovery Vault and account media**.
- A compromised target signing key can forge a self-reported wipe; do not transform receipt status into certified physical erasure.
- Genuine PostgreSQL18 two-PHP-process signed-command races have been **verified 3/3** on the exact own test code; still missing are atomic integration with #80 signed revoke, cross-device offline delivery/actual local wipe and physical iOS/Android.

## Two-process race discovery and regression

**A second QA failure was found:** Laravel's registered CLI handler logged the uncaught harness exception without making the GitHub job fail; GitHub incorrectly marked the PG job green. That prior run must NEVER be counted as 3/3 PASS. Original evidence remains linked above.
