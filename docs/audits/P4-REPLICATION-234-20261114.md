## Internal actual-copy contract

This server-only service is NOT wired to any route, worker, cron, UI or automatic provider registration. Only a trusted caller may supply the account and database location IDs and server-owned adapter bindings; arbitrary endpoints/browser credentials are not supported.

1. enqueue requires ready identity account under PostgreSQL FOR UPDATE, account ownership of active PhotoObject or MediaChunk, unexpired TTL, no tombstone, canonical immutable source bytes/SHA256, registered verified source, registered reserved/degraded target, different providers and declared failure domains. Account+request-key idempotency digest, unique target generation and persisted immutable content metadata.
2. process claims a durable 120s lease with a hashed token and bounded retry/backoff/attempt metadata. Stale expired workers cannot overwrite another worker's lease.
3. Before ANY second-provider write, source ciphertext is streamed with an 8 MiB cap, SHA256 and full byte count validation into a ciphertext-only bounded temporary stream. No decryption or plaintext.
4. If the second-provider object already exists and passes a fresh entire GET/hash, an independently verified lost-ACK reconciliation skips the repeat PUT. Otherwise transfer ciphertext, then GET and hash the destination; do not trust PUT or HEAD alone as evidence.
5. Success rechecks identity, owner, TTL, tombstone, logical object, checksum, source and target location identity/metadata and object keys under the account lock. Only the destination location state is promoted to verified after an actual physical readback. Original source data is neither deleted nor replaced.
6. Failed/missing/corrupted source, missing or altered destination, provider outage, account revocation, tombstone, stale lease, changed object locator cannot report a verified ACK. A bounded generic failure classification is recorded for retry; no S3 raw exception details, credentials, plaintext or object paths are returned in metadata.
7. A new generation can repair an explicitly degraded destination. This is **live ciphertext replication, not an account Recovery Vault backup**. No guarantee of an independent provider failure domain from adapter-supplied labels alone.

Remaining risk: the existing StorageManager uploader does NOT participate in the lease or an independent active placement generation. During a race or TTL cleanup, a target may be uploaded physically but not ACKed, leaving an orphan for a future garbage collector. This slice is not production-ready or authorized to be exposed.

**Internal explicit-only selection:** caller creates the dispatcher with a trusted server-owned `CiphertextReplicaCoordinator` and invokes `dispatch(trustedNow,maxJobs,maxBytes,maxPerAccount,maxAttempts)` with trusted operational limits. Hard per-call maximums: 16 jobs, 64 MiB byte budget, 2 jobs per account, 12 attempts allowed, and a finite 192-result scan; individual ciphertext object limit 8 MiB as in coordinator. Invalid limits fail closed *before* DB/network IO. Query admits only ready accounts and eligible `queued`/`retry` items due by `next_attempt_at`, or `leased` with an actually expired `lease_until`, excluding over-attempt and oversized jobs. Uses `ROW_NUMBER() OVER(PARTITION BY account_id...)` to prioritise rank-1 due jobs from distinct accounts before rank-2 jobs so a single account cannot monopolize the bounded window. Deterministic due-time/creation/id ordering, whole-object byte budget without overflow, no surprise retry before its durable deadline.

Each selected job is passed to **unchanged** real `CiphertextReplicaCoordinator::process()`, which independently rechecks the PG account lock, per-job lease, TTL/tombstones, physical source readback, destination full GET/hash and durable ACK. No simulated delivery, no new S3 calls outside the coordinator. Returned data are **sanitized observed counters**, not IDs, object keys, failure messages, verified S3 provider domain or a proof that this dispatcher initiated the successful IO. The return explicitly says `noAutomaticScheduling=true` and `globalRateLimitEnforced=false`.
