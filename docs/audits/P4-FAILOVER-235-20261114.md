## What is implemented (isolated, unmounted)

New App\Storage\Failover\ReplicaReadPreflight::inspect:
1. Trusted server-side account, asset and location IDs. No browser-supplied object path, endpoint, credentials or provider registry. Supports live photo objects and media chunks.
2. Read-only canonical DB check: account ready, parent and asset active, TTL not expired, tombstone absent; two distinct locations, matching logical ciphertext SHA/byte count, verified replica state.
3. Trusted server-owned adapter registry requires distinct providers and declared failure domains and positive credential revisions. Distinct labels are not proof of administrative or geographic independence.
4. Reads only replica transport (primary can physically be unavailable), verifies exists/size/full-stream SHA-256 with 8MiB hard cap and discards the ciphertext; no writes, status promotion, pointer changes or plaintext access.
5. Rechecks canonical DB after physical IO for revoke/delete/TTL/location changes. Errors fail closed and sanitize adapter exceptions.
6. Returns status=replica_physical_preflight_only, physicallyVerified=true, failoverAuthorized=false. No browser route or StorageManager invocation is wired.

**Security limitations:** The readback observes a state at two times, not an atomic signed receipt or production authorization. A later write, expiry, deletion, credential rotation, provider failure-domain misconfiguration or concurrent assignment of a new active generation can invalidate it. Actual failover must implement account-scoped generation fencing, signed receipt/credential rev checks, recheck on the live read path, ACL and privacy-safe status. There is no independent S3 test on this branch, no provider outage/recovery demonstrated and no actual service activation.
