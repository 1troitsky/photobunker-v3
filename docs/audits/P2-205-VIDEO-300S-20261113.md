# P2 Issue #205 — isolated 300-second video capture limit

Date: 2026-11-13. Base: accepted `main@6565a0fe852882ea5fc26e493df81affed687eee` after #293. Product branch: `p2/205-video-300s-guard`. No main modification, merge or deployment.

## Baseline / problem

`CaptureView.vue` used a shared 175000ms limit for both video and audio although `ts.md` section 14 requires 5–300s video and 5–3000s audio. Media envelopes independently enforce `MAX_MEDIA_BYTES=128MiB`. Simply increasing a timer without bounding the requested encoder bitrate can force oversized in-memory blobs, and a browser is free to ignore MediaRecorder bitrate hints.

## Implemented narrow product slice

1. Added `apps/web/src/features/media/domain/capture-recording-policy.ts` with a mode-specific **video 300000ms** cap and conservative MediaRecorder video 2.4Mbps / audio 96kbps request (~93.6MB for five minutes if honored).
2. Existing audio recording still capped at 175000ms. Issue #206 is responsible for the separate 3000-second audio implementation and requires chunking/low-memory guarantees.
3. `CaptureView.vue` now uses the selected mode's same duration in the stop timer and elapsed-time validator, without altering the existing strict 128MiB E2EE media cap, ondataavailable oversize rejection, account identity, GPS consent, assignment policy, or encrypted outbox.
4. Added focused unit tests for duration, advisory data budget, audio isolation and per-recorder mutable options.

## Validation and limits

All existing tests remain enabled. **Exact-head CI has not been verified yet; no PASS claim for these changes until workflow runs finish.** No iOS Safari / physical Android native 300s recording and no full 300s multi-device S3 ciphertext readback evidence. MediaRecorder can ignore bitrate hints: the hard size limit remains authoritative; oversize recording is discarded (not silently truncated or uploaded). Captured parts are buffered in JS and can fail under memory pressure. There is no durable partial recording on page reload. This remains a **PARTIAL** #205 product slice, not full signed-off acceptance.
