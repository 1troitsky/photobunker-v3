## Trusted-session transaction admission primitive (INTERNAL) — 2026-11-14

`apps/api/app/Administration/Restrictions/TransactionBoundRestrictionAdmission.php` adds a narrow **fail-closed precondition for ALREADY server-authenticated account/device identities**, never a token or session authenticator. It rejects `DB::transactionLevel() < 1` with `admin.restriction_transaction_required`, then calls existing account/device restrictions+identity revocation admission using their `SELECT ... FOR SHARE` locks inside the current caller-owned default Laravel DB transaction. The nested admission savepoint does not release PostgreSQL account/device locks until the caller commits the outer DB transaction; a later admin `FOR UPDATE` cannot interleave a new restriction before same-transaction protected SQL. A middleware or autocommit read is deliberately rejected. The caller must independently prove user identity and use the same DB connection; **external S3/Matrix requests, other connections, separate transactions, long network IO and offline outbox cannot be treated as protected by this DB-only primitive**.
