## Independently supplied checkpoint / anti-equivocation — 2026-11-13

The previous external minimum sequence alone could permit two **genuinely signed, different manifests with the same release_sequence**. `verifyRelease()` now optionally accepts `trustedCheckpoint: {releaseSequence, manifestSha256}` as a second externally authenticated policy input; the CLI supports paired `--trusted-checkpoint-sequence` and `--trusted-checkpoint-sha256`. It rejects signed earlier releases as `ROLLBACK`, rejects a different validly signed manifest at the same checkpoint sequence as `RELEASE_EQUIVOCATION`, and rejects missing/malformed external checkpoint fields rather than silently dropping policy. A higher sequence remains allowed; this tool never writes the new trust floor or authorizes its promotion.
