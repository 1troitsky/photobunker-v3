The intent is canonical, strictly versioned, P-256 ECDSA-signed under a new domain `photobunker.panic.intent.v1\n` with account/device/revision/operation UUID, 32-byte nonce and ISO timestamp binding. Explicit immutable scope: delete **all live cloud locations only**; **preserve existing verified Recovery Vault**. No plaintext PIN, Recovery Key or media is included. Public-key verification takes a trusted device SPKI from outside the wire payload. Noncanonical, cross-account/device, revision-mismatch, wrong-signature, unexpected field, alternate purpose, backup deletion, future-time and collision negatives fail closed. Old signed intents are parseable after offline delay; eventual server authorization and atomic replay ledger remain mandatory.

## Second owned slice — durable PRE-DISPATCH intent journal (CHAT-G, 2026-11-14)

**New exclusive files:** `apps/web/src/features/panic/infrastructure/panic-intent-outbox.ts` and `apps/web/src/features/panic/infrastructure/panic-intent-outbox.test.ts`. Exactly five own paths in current Draft #315, including this report.

- Dedicated `pb3-panic-intent-prepared-v1` IndexedDB database, intentionally separate from regular photo/media caches scheduled for future wipe. Stores ONLY signed envelope + its account/device/revision/UUID and local timestamp; no plaintext media, PIN, private keys, Recovery Key, backup keys, network access or server receipt.
- Device-specific write-once slot and unique operation index. IndexedDB read-modify-write in Dexie transaction serializes concurrent tabs; same original signature retries idempotently, a different signed command is an explicit `panic.prepared_conflict`. No replacement or deletion path; future server-ack lifecycle still needs a separate approved implementation.
- `prepare` validates against externally trusted registered device SPKI and expected account/device/revision, persists, then reads/verifies original bytes before returning. IndexedDB failure/corruption throws; offline reload can use `read` only with a fresh trusted scope and key. No auto-flush, no claim of server ACK, no local/cloud deletion.
- This does NOT itself implement secure emergency `local_locked`, cross-tab cancellation of active camera, post-key-destruction trusted recovery context, device revoke, server-side replay, queued transport, GC or loss-resistant OS persistence. IndexedDB may be removed by a browser/OS; this module is not a durable remote delivery promise. No production use until separate integration/audit.
