## Critical limitations — no false security acceptance

**This is an internally consistent, application append-only DB log, NOT an externally tamper-evident audit service and NOT a functioning admin feature.** SHA-256 alone does not prevent a privileged DB attacker from rewriting records, recomputing all hashes and updating the head. No external signed/checkpointed witness/trust anchor exists; `verifyChain` detects mismatches and accidental/tail modifications, not a fully privileged attacker. This PR does not create an independently authenticated MFA session, revoke/rotate actual operator grants, validate a real login or connect AdminPrincipal to a trusted session. Synthetic principals in tests are NOT evidence of real user/operator MFA. There is no real admin HTTP route, CSRF/same-origin acceptance, entitlement override, block/ban/revoke, remote wipe, billing action, read access to E2EE plaintext/Recovery Key/media/GPS/IP, production credentials or deployment. No destructive action occurred.

**Remaining for full #227:** real independently authenticated and expiring admin session + MFA/step-up adapter, server-trusted persistent role grants (not request-derived role string), isolated admin subdomain/route permissions and CSRF, append-before/after authorized action coupling, external tamper-evident digest anchor and independent audit, privilege/role lifecycle acceptance including concurrent revocation, actual real-user routes/UI and production device/security QA. Only those gates can turn this record store into a production Admin workflow; explicit owner approval required for any merge/deploy or destructive operation.
