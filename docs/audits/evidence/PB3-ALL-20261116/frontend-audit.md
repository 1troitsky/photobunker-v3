**F02 — HIGH, семантика #402 не эквивалентна в #412.** Это вывод по коду, не по удалённому имени `logout-fence.ts`. В #412 `logout()` ждёт `markSignedOut()` до скрытия UI, что защищает обычный awaited path. Но `requireSession()`/`activate()` не проверяют synchronous origin fence, нет `storage` listener для блокировки соседней вкладки; `resumeLocalDevice()` не перепроверяет `isSignedOut` после async `openDevice`, а stale login proof не проверяет durable marker перед повторной активацией. Например, выход во вкладке B сам по себе не очищает `activeSession` уже открытой вкладки A. Candidate #402 содержит эти барьеры и отдельные негативные тесты. Dynamic #412 reproduction здесь NOT TESTED. При будущей интеграции сохранить #402 invariants и тесты, согласовав с новым bootstrap/signout UX; не заменять `session.ts` целиком.
