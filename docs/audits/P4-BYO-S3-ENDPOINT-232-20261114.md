## Critical boundary — no SSRF claim without transport integration

DNS results are trustworthy only after caller independently resolves all CNAME-to-A/AAAA records; reject if any answer is unsafe. The future S3 transport must:

1. Bind a short-lived authorized result to the current account/storage-location request. Never let browser supply allowedPorts or trusted DNS RR set.
2. Dial the approved IP directly, preserve original DNS hostname for TLS SNI, certificate hostname verification and HTTP Host. Verify actual peer using assertConnectedPeer, on retries, connection pool reuse and virtual-host/bucket addressing.
3. Disable automatic redirects for all S3 operations; otherwise a validated host can redirect to internal networks. Never re-resolve to an unpinned address after failure.
4. Enforce entitlement, account-scoped storage grant, secret vault, credential rotation, quotas, signed ciphertext, and timeouts before allowing test PUT/HEAD/GET/DELETE. Keep ciphertext-only bytes; never expose credentials to frontend or logs.

This slice DOES NOT perform DNS lookups, connect to S3, certify network paths, persist credentials, enforce TLS at SDK transport, create a StorageLocation or test bucket access. It is NOT a completed BYO feature.
