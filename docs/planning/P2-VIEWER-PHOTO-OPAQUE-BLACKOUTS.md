# P2 Viewer V-10 — private-only opaque blackout regions

**Status:** DRAFT. No safe/public publish feature enabled or accepted. Parent Photo Editor stack #102–#104 exact-head green; CI/native acceptance for this increment required.

## Product contract
- The owner may add, select, drag, change x/y/width/height, undo/redo, or remove up to 12 **fully opaque rectangular blackouts** on a temporarily decoded/cropped personal JPEG. Normalized percentage coordinates, minimum 5% per side, strictly bounded to image. No semi-transparent masks, blur, CSS-only safe image or automatic public version.
- Blackout overlays in the editor exist solely in memory. On **explicit** Save encrypted in Browser or **explicitly confirmed** plaintext device download, all text, shapes, strokes and blackouts are flattened in **one** fresh canvas JPEG encode. **Blackout pixel replacement happens LAST**, including over any painting/text/shapes under the rectangle. The original ciphertext JPEG and its original photo/media records, grants, GPS and assignment provenance are never altered or inherited. Source EXIF/metadata must not be included in the new raster JPEG.
- The new independent personal MediaFile is queued using the already-reviewed signed AES-GCM durable outbox; a local queued state must not be presented as cloud ACK. No automatic share, recipient key grant, public URL, safe/original mode switch, irreversible source purge, source access revocation, or production GC occurs.
- A user may still open the original through the normal owner authorized viewer. **A masked JPEG is NOT a complete privacy guarantee** if the original remains shared elsewhere. A secure Safe Media publication workflow must independently enforce ACL/source original nonexposure, verified derivative checksum+metadata, publication scopes and revocation; none is authorized in this PR.
- When comparing Before, original remains clearly identified and Save/Download masked variant is hidden; returning to After restores editable mask positions. After Save, editor shows the **actual** rendered blackened JPEG rather than a CSS overlay. Logout/route/key changes revoke temporary object URLs and clear all nonencrypted in-memory marks.
- Filename suffix `-blackout.jpg` communicates only local processing, NOT authorized public-safe classification. No plaintext mask JSON goes to backend/IndexedDB or analytics. Blackout settings retained only in bounded volatile 50-snapshot Undo/Redo history.

## Security and verification
- Up to 12 UUID marks; integer x/y 0–95, width/height 5–100 constrained by x+width/y+height <=100. Any malformed/unknown JSON property/duplicate/negative/partial/translucent coordinates fail closed. 4096px per axis and 16MP decoded output limit.
- Canvas uses opaque **#000000 fillRect** with floor left/top and ceil right/bottom; even uneven pixel grids get fully covered. All source pixels under the region are overwritten **before JPEG encoding**, no CSS-only illusion. However, neighboring JPEG compression behavior and the user's source file outside the derivative remain separate concerns.
- Unit tests: exact rounded coverage, size and shape validation, invalid opacity, duplicates, strict bounds and context restore.
- Real Chromium/PG18/Garage: generate saturated 320x240 JPEG, encrypt on device warm offline; add/delete/undo/redo/edit/drag a blackout; Before compares to original; explicit E2EE save of a separate JPEG. Decrypt actual bytes: fully black interior and remaining red outside, identical source SHA-256, no inherited original metadata, queued state, no implicit download. Confirm OS download separately, then logout and verify temporary Blob URL revoked.
- Owner acceptance, native Safari/iOS/Android, public-safe derivative authorization/ACL, source version replacement, source revocation and physical GC are NOT TESTED/NOT IMPLEMENTED. Do not merge to main without explicit owner approval.
