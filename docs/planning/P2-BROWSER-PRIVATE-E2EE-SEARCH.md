# P2 Browser — приватный поиск по метаданным (Draft #93)

**Статус:** интегрированный код в Draft, не финальная пользовательская приёмка. Основание: `ts.md §12`. Matrix, платежи и физический GC не затрагиваются.

## Почему без серверного поиска

Сервер не хранит открытые `fileName`, `description`, `category`, `tags` или GPS. Поисковую строку нельзя отправлять в API, URL, query-string, серверный лог, телеметрию или сторонний индекс. Существующий публичный Browser индекс содержит только непрозрачные ID, типы медиа, подтверждённые сроки хранения и состояние.

**Допустимый компромисс первой версии:** пользователь ищет в **загруженной части каталога/текущей папке/вкладке и фильтре**, а не обещанным «глобальным индексом». Поиск начинается со второго символа приватного поля; ID фильтруется сразу.

## Поток данных и безопасность

1. Browser получает только разрешённые авторизованному аккаунту непрозрачные ID через существующие `/photos/v1`, `/media/v1` и `/browser/v1/archive` эндпоинты. Поисковая строка ни в один из них не передаётся.
2. Для каждого подходящего ID считываются **только** зашифрованные метаданные из локального outbox либо соответствующего облачного объекта. Фото: отдельный `metadata` asset. Видео/аудио: отдельный AES-GCM `metadata` chunk. Облачное видео/аудио использует authenticated manifest + server receipt и единственный metadata chunk, не загружает все media chunks.
3. Проверяются versioned contract, account ID, expiry, SHA-256 ciphertext и AES-GCM AAD (включая индекс и число чанков); затем расшифровка ключом аккаунта на устройстве. Дешифрованный временный buffer зануляется. Протокол `media` и текущие ключи/формат S3 не изменяются.
4. Нормализация NFKC, строчные буквы, поиск всех введённых слов по имени/категории/описанию/тегам; для фото имя не создаётся искусственно, но фото-ID участвует в обычном фильтре.
5. Результат — только `Set<opaque file key>` и счётчики проверенных/ошибок/недоступных. **Нет незашифрованного персистентного индекса, поисковой истории или кэша метаданных.** Функции не логируют приватные строки.
6. 250-мс debounce, максимум 3 одновременных E2EE чтения, максимум 200 загруженных записей на запрос. При смене аккаунта, устройства, повторной авторизации или запроса результаты предыдущего поколения игнорируются, а следующие запросы не запускаются.
7. При недоступности/порче метаданных UI сообщает **неполный** результат вместо «не найдено». Локальные записи доступны офлайн; для cloud-only требуется авторизованная онлайн-сессия. Если локальная копия испорчена и доступен тот же файл в облаке, проверяется только облачный metadata chunk.

### Не делаем и не обещаем

- Нет серверного поиска по секретам, серверного plaintext индекса, поиска по GPS-координатам, пользовательским именам команд или зашифрованным заданиям: соответствующие приватные поля пока не интегрированы в этот контракт.
- Нет «поиска по всему аккаунту» с автоматической выгрузкой каждой страницы: ограничение в 200 локально загруженных файлов и счётчик оставшихся явно отображаются. Расширять через cursor/pagination только после UX и performance-приёмки, сохраняя E2EE.
- Нет хранения незашифрованных метаданных в IndexedDB даже «для ускорения». Временная in-memory выборка сбрасывается при смене запроса/сессии, lifecycle компонента.
- Закрытый доступ, истёкший TTL, неподтверждённый объект и физический GC не обходятся поиском; архив и каталог используют прежние ACL, CAS и deadline правила.
- Не считать Chromium/Linux достаточной Safari/iOS/Android security-приёмкой. Не считать отсутствие plaintext в HTTP достаточным доказательством отсутствия всех браузерных/OS побочных следов.

## Проверки

- Unit: приватные поля и Unicode, ID-фильтр, локальный офлайн-доступ, облачная metadata-only выдача, аккаунтная изоляция, отмена запросов, испорченный ciphertext, partial results, лимит 200.
- Crypto: видео больше 1 MiB, metadata-only AES-GCM без data chunks, неправильный account, повреждённая SHA-256 и IV.
- Chromium + PostgreSQL 18/Garage: импорт аудио с приватными именем/категорией/описанием/тегами, офлайн-поиск, Recovery Key на другом устройстве, облачный поиск по ciphertext, отсутствие приватного текста в HTTP.
- Статус CI и точные SHA фиксируются в PR #93; этот документ не является второй таблицей прогресса.

**Отдельные будущие задачи:** зашифрованные индексы для больших каталогов и их безопасная инвалидация при revoke/retention, метаданные заданий, поисковая область «Все папки» и search pagination.
