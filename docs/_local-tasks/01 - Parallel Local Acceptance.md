# PB3 — Parallel Local Acceptance & Testing

Репозиторий: `1troitsky/photobunker-v3`

Исходная ветка: `p1/04-assignment-e2ee-capture`

Исходный commit: `e72c350d8926bcac17c515acef6eb1dc884c6206`

Новая ветка: `qa/p1-local-acceptance`

## Контекст

ChatGPT параллельно продолжает разработку P1-04 в отдельной ветке `p1/04-signed-capture-policy` (Draft PR #12).

**Твоя задача — независимо заниматься локальным тестированием, автоматизацией проверок и улучшением воспроизводимости тестовой среды.**

Не жди результатов ChatGPT. Не вмешивайся в его код и не синхронизируй рабочие ветки в процессе.

## 1. Подготовка окружения

Прочитай `AGENTS.md`, `ts.md`, документацию P0–P1-04 и существующие CI workflow.

Проверь локальные зависимости, Docker, PHP, Composer, Node.js, pnpm, PostgreSQL и Garage.

Подними изолированную тестовую среду PB3, не затрагивая существующие контейнеры, базы и пользовательские данные.

Запусти Laravel, Vue, PostgreSQL 18 и Garage S3.

## 2. Полный тестовый прогон

Выполни существующие PHPUnit, Vitest, TypeScript, production build, Playwright и интеграционные проверки.

Проверь основной сценарий:

- A создаёт анонимный аккаунт и задание на 30 фото.
- B регистрируется и принимает приглашение после проверки fingerprint.
- B делает фото при отключённой сети.
- Фото сохраняется локально в зашифрованном виде.
- После восстановления сети происходит синхронизация.
- B передаёт фотографию A через отдельный E2EE grant.
- A расшифровывает полученный снимок.
- C не получает доступа к данным.
- Отзыв доступа запрещает последующие серверные чтения.

Дополнительно проверь reload, потерю сети, повторную отправку операций, ошибки API, сохранение локальной очереди и изоляцию аккаунтов.

## 3. Браузеры и устройства

Проверь реальные браузеры Chromium и Safari (если Safari доступен), а также мобильные размеры экрана.

Особенно важны camera permissions, IndexedDB, offline/reload, восстановление сессии, обработка ошибок камеры и отсутствие записи в системную галерею.

Если доступен физический iPhone, проведи отдельный ручной тест. Если нет — явно отметь NOT TESTED. Эмуляция не заменяет проверку устройства.

## 4. Сделай полезную автоматизацию

Не ограничивайся отчётом.

Создай воспроизводимый локальный acceptance harness, который позволит запускать необходимые проверки повторно одной документированной командой.

Размещай собственные скрипты и новые тесты только в отдельных директориях:

- `scripts/local-acceptance/`
- `tests/local-acceptance/`
- `docs/audits/`

Повторно используй существующие CI и тестовые утилиты. Не дублируй инфраструктуру без причины.

## 5. Границы параллельной работы

**Запрещено изменять:**

- `apps/api/`
- `apps/web/src/`
- существующие продуктовые E2E-тесты
- `ts.md`
- `main`
- PR #11 и PR #12

Если обнаружена ошибка продуктового кода, зафиксируй её с точными шагами воспроизведения и ожидаемым поведением. Не исправляй продуктовый код в своей ветке — этим параллельно занимается ChatGPT.

Для критических дефектов укажи P0/P1 severity и конкретный блокирующий сценарий.

## 6. Результат

Создай `docs/audits/P1-LOCAL-ACCEPTANCE.md`, содержащий:

1. Проверенные версии зависимостей и окружения.
2. Команды воспроизведения тестов.
3. Таблицу PASS / FAIL / NOT TESTED.
4. Найденные дефекты с приоритетами.
5. Проблемы безопасности, offline и сохранности данных.
6. Результаты реальных браузерных проверок.
7. Список ограничений тестирования.

Создай один Draft PR из `qa/p1-local-acceptance` в `p1/04-assignment-e2ee-capture`.

Не выполняй merge, deploy или опасные операции с данными.

**Главное:** выполни всю доступную работу самостоятельно. При обнаружении ошибок не останавливай остальные независимые проверки. В конце предоставь ссылку на Draft PR и краткий список обнаруженных блокеров.
