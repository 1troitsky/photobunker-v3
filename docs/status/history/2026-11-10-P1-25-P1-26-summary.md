## Что теперь действительно работает

- P1-25: `/contacts` — единый экран «Контакты и Команды» с настоящими контактами, проверкой owner-signed ECDH key directory и независимым подтверждением отпечатка. Точный UUID lookup; локальный псевдоним, encrypted-on-device contacts index, offline просмотр/переименование/удаление, жёсткая изоляция по account AKEK и проверка pin на каждом чтении.
- P1-26: Fieldwork Editor → **Участники** читает подтверждённые контакты из AES-GCM IndexedDB и отображает их как реальные варианты выбора. Нажатие **Выбрать** только заполняет UUID, повторно проверяя текущую подписанную key directory. Никакого server invite, ACL/membership/media DEK на этом шаге не создаётся.
- **Только явная отдельная команда** «Отправить подписанное приглашение» ставит owner-signed намерение в прежнюю локальную durable outbox; сервер проверяет существующий contributor role, текущую descriptor hash и consent. B самостоятельно сверяет ключ владельца и принимает приглашение; доступ к media оригиналам не появляется сам.
- Данные aliases/contact-list/peer UUID хранятся в **новой книге** только шифртекстом. Существующая **отдельная база подтверждённых key pins** содержит публичные peer IDs/fingerprint и не переименована в «полностью скрытый контактный граф»; для production нужна независимая privacy оценка всех локальных метаданных и backup/restore.
- В принятый shell перенесена единая навигация, но **Teams/Blacklist disabled** пока нет реальных серверных TeamMember/ACL и ключевого отзыва. Поиск @username/#UserID и межустройственная синхронизация остаются открытыми задачами.

Нет универсального privacy-aware `@username/#UserID` lookup, server-authoritative Teams/roles/Blacklist, межустройственной синхронизации контактов, криптографического отзыва уже раскрытых ключей, contributor-owned original GC, полноценной native Safari/iPhone/Android QA, external crypto/security review, owner acceptance, merge в main и deployment. Публичные E2EE pins и серверные lookup requests не означают полной анонимности социального графа.
