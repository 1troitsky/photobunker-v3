## Сделано

- **P1-22:** редактор Fieldwork **Файлы** редактирует отдельные E2EE-инструкции для фото, видео, аудио. Версия приватного plaintext v2 сохраняется как новый зашифрованный AEAD-пакет в существующей подписанной owner-account истории P1-19. Старые v1 читаются, старые согласованные ECDH-приглашения продолжают расшифровывать обновление с неизменным DEK. Исполнитель видит только расшифрованные инструкции разрешённых видов; warm-offline cache шифруется отдельно и привязан к signed ревизии. Нет plaintext в API/outbox.
- **P1-23:** owner-only серверный paginated roster приглашений; исходный подписанный owner payload проверяется у клиента, live accepted/pending статусы определяются сервером. 404 постороннему, включая принятого исполнителя. Нет офлайн-выдуманного «принято», нет автоматического E2EE доступа к файлам, нет отзыва полученных ранее ключей.
- **Интеграционный дефект исправлен:** при открытии редактора через полную перезагрузку аккаунт сначала восстанавливался offline, потом online, но same-identity переход не вызывал повторное обновление roster. Добавлена безопасная revalidation без потери несохранённых редакторских правок.

## Не завершено и следующие границы

- **Только автоматизированная проверка:** физический iPhone/Android, native Safari, cold offline bootstrap, внешняя крипторевизия, BYO/replica S3, production не проверены. Роли куратор/наблюдатель, команды и revocation/key-epoch protocol ещё OPEN. Подписанное приглашение к заданию не даёт доступа к media-файлам автоматически.
- **Никакого физического удаления чужих оригиналов:** assignment-owner не владеет файлами contributor; P1-21 ledger лишь фиксирует логические сроки. Отдельный contributor-authorized deletion protocol и verified multi-provider GC требуют отдельного решения/аудита.
- **Следующее:** безопасный Fieldwork UX-parity для выполнения заданий, независимый локальный аудит интеграции цепочки и затем **только по прямому разрешению владельца** упорядоченное слияние проверенных блоков в main.
