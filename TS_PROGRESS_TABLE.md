## Ближайший порядок работы

1. Продолжать только независимые свободные Issues по свежим CLAIM в [#302](https://github.com/1troitsky/photobunker-v3/issues/302); не считать отдельные Stage/Draft за готовый функционал. Отдельно сверять parent-child PR (например #353→#362) и shared-path конфликты.
2. Накопить проверенные Drafts до **одного согласованного интеграционного пакета**, проверить exact heads, зависимости, security, PG18/Garage и браузерную E2E приёмку. [#337](https://github.com/1troitsky/photobunker-v3/issues/337) — исходный аудит старых PR, не актуальное автоматическое разрешение слияния новых.
3. **Никто не меняет `main`, не делает merge/deploy/destructive operations без явного разрешения владельца.** После разрешённой интеграции — новый main CI, обновить эту таблицу в своей ветке и снова сверить P1–P4 с `ts.md`.
4. PB3 **НЕ ГОТОВ К РЕЛИЗУ**, пока обязательные E2EE/security/storage/payment/mobile/recovery gates остаются FAIL/BLOCKED/NOT TESTED. Полный перечень требований: [`ts.md`](ts.md) и [`AGENTS.md`](AGENTS.md).

**Документ обновлён только для статуса, а не для подмены QA:** каждое утверждение относится либо к текущему `main`, либо к **явно названному Draft PR**. Историческая [PR #294](https://github.com/1troitsky/photobunker-v3/pull/294) не является источником этого среза.
